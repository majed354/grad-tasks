# خطة منتج: صورة الطالب الكاملة

قرار المستخدم في 25 أكتوبر 2026: جميع برامج الدراسات العليا، والكود في `grad-tasks`، والمجلد المحلي المعتمد «مهام الدراسات العليا»، والنشر من GitHub على Netlify.

## وحدة العمل

المحور هو **قيد الطالب في برنامج ودرجة**. يمكن للشخص الانتقال من الماجستير إلى الدكتوراه دون خلط الملفين. يبدأ المنسق من البحث أو لوحة المهام، ويصل إلى ملف يجمع بيانات القبول والسجل الأكاديمي والرسالة والإشراف والقرارات والمتابعات وروابط الوثائق. يمكن إنشاء تقرير لسجل واحد أو مجموعة مصفاة دون إعادة إدخال البيانات في ملف منفصل.

## لماذا نحتاج أكثر من جدول أسماء؟

السجل الحالي والقرار التاريخي والمعلومة المجمعة ثلاثة أنواع مختلفة. تغيير المشرف أو اعتماد خطة يحتاج دليلًا وتاريخًا، والمقرر يحتاج فصلًا وحالة مسجلة، والاستطلاع المجمع لا يصبح وصفًا لطالب. لذلك تحفظ السجلات المرتبطة مستقلة داخل الملف، وتحفظ الخانات الناقصة فارغة، ولا تستخدم الأصفار لتمثيل الغياب.

## المرحلة الأولى — منفذة

الواجهة العربية، السجل، ملف الطالب، المقررات، المهام والمواعيد، القرارات، روابط الوثائق، المتابعات، الاستيراد بمراجعة، والتصدير المخصص والطباعة. حفظ محلي مع منع الكتابة المتعارضة من تبويبين، وتجربة افتراضية منفصلة، ومستودع وبناء جاهز لنتلفاي. لا بيانات طلاب حقيقية في الكود.

هذه المرحلة تسمح بمراجعة نموذج العمل وتجهيز أول ملف بيانات من دون كشف السجلات في مستودع عام. يمكن جمع ملفات المصدر في المجلد المحلي المستثنى ثم تحديد أعمدتها ومراجعة الاستيراد.

## المرحلة الثانية — التشغيل المشترك

قرار 27 أكتوبر 2026: اختار المستخدم رمزًا مشتركًا للجميع بالصلاحيات نفسها. أضيفت واختبرت محليًا طبقة Postgres وAPI وجلسة خادم وحفظ ذري يمنع تعارض الأجهزة، لكن Netlify رفض إنشاء قاعدة البيانات للحساب الحالي ولم تنشر النسخة أو تنقل بيانات الإنتاج. التحقق والعائق في `PROJECT_LOG.md`. تبقى الحسابات الشخصية وصلاحيات البرامج وتوثيق منفذ العملية باسمه عناصر مستقبلية في القائمة أدناه، ولا ينفذها الرمز المشترك.

القرار النهائي اللاحق في اليوم نفسه: **SharePoint وحده مصدر حفظ التعديلات**، مع بقاء الرمز الموحد. نُقلت نسخة كاملة مؤكدة إلى المجلد المؤسسي، لكن الربط التلقائي لم يفعل. Google Sheets ليس مصدر عمل معتمدًا. يحتاج استمرار واجهة Netlify إلى تفويض تطبيق خلفي محدود بالمجلد؛ فحص الحساب رفض تسجيل تطبيقات Entra. تشغيل الواجهة داخليًا عبر SPFx بديل يتطلب صلاحية نشر حزمة مخصصة، ولم يظهر خيار رفعها في كتالوج الحساب. لا تحول الواجهة إلى قوائم SharePoint أو تضف اشتراكًا أو مخزنًا آخر تلقائيًا.

بحث البدائل دون مسؤول: رفض الحساب أيضًا تفويض تطبيق rclone الجاهز بالخطأ `AADSTS90095`، ولم تمنح صلاحيات. إنشاء صفحة Web Part كلاسيكية متاح، لكن محرري Script Editor وContent Editor غير ظاهرين. Power Apps Canvas مع موصل SharePoint القياسي مرشح لواجهة داخل Microsoft 365، بشرط التحقق من ترخيص المستخدم والبيئة وإنشاء وحفظ نموذج تجريبي أولًا. يحتاج تسجيل دخول Microsoft وصلاحيات المصدر، والرمز الموحد سيكون بوابة إضافية؛ لا يعد بديلًا مطابقًا للواجهة الحالية أو حلًا مُثبتًا بعد. Power Apps Code Apps الذي يمكنه تشغيل React يحتاج تفعيلًا إداريًا وترخيصًا مؤهلًا، فلا يفترض إتاحته من مجرد ظهور قائمة Power Apps. لا تستخدم استخراج رموز جلسة المتصفح أو تمكين نصوص مخصصة للتحايل على قيود الموقع.

1. تحديد من يستخدم النظام: مشرف عام، منسق برنامج، قارئ، وهل يحق للطالب الدخول أصلًا.
2. مصادقة موثوقة وصلاحيات على الخادم لكل طلب وملف وتصدير؛ لا يعتمد المنع على واجهة المتصفح.
3. وظائف Netlify كطبقة API وقاعدة Postgres خاصة، ومخزن خاص للملفات وروابط قصيرة الأجل إن احتجنا رفعًا فعليًا. اختيار موضع الاستضافة وسياسة الاحتفاظ يسبق نقل البيانات الحقيقية.
4. فصل الشخص عن قيوده، ومراجع البرامج والخطط والمشرفين بمعرفات ثابتة. هوية المستخدم من المصادقة، والتعديل بإصدار متوقع داخل معاملة لمنع فقد التعديلات.
5. سجل تدقيق على الخادم لا يستطيع المستخدم العادي تعديله، ونسخ احتياطية واختبار استعادة، وسجل لعمليات التصدير.
6. ترحيل نسخة JSON عبر عملية مراجعة إلى الخادم. لا ترفع قاعدة البيانات أو نسخها إلى GitHub.

## المرحلة الثالثة — الاستكمال من المصادر

لكل مصدر موصل مستقل: وصول مصرح، لقطة بتاريخ وبصمة، تحويل إلى عقد موحد، مطابقة مثبتة، قائمة تعارضات، مراجعة واعتماد، ثم حفظ. يظل الاستيراد غير المعتمد خارج ملف الطالب الفعلي. أولويات الربط: سجل الطلاب الرسمي، ثم الخطط، ثم قرارات المجالس، ثم الإشراف والرسائل. مؤشرات البرنامج والاستطلاعات سياق مجمع منفصل.

## المرحلة الرابعة — التقارير المتقدمة

قوالب معتمدة لتقارير التقدم، أعباء الإشراف، جاهزية المناقشة، متابعة الخريجين والقرارات. تقارير Word قابلة للتحرير عند تحديد القوالب، وإرسال أو تنبيهات فقط عند تحديد المستلم والمحتوى والتفويض. لا تضاف مدة نظامية أو قاعدة أهلية قبل توفير مرجع معتمد بإصداره.

## المعلومات المطلوبة عند بدء جمع البيانات الفعلية

أول كشف طلاب مع تعريف الأعمدة وتاريخ الاستخراج، قائمة البرامج وأكوادها والخطط، تعريف الحالات، سجل المشرفين بمعرفاتهم، وصيغة قرارات الرسائل. الحقول الاختيارية تبقى اختيارية، ولا نستنتج الجنس أو الجنسية أو حالة الطالب من الاسم. يمكن بدء الاستيراد بحد أدنى: الرقم الجامعي، الاسم، البرنامج، الدرجة.
